**Project:** Restaurant Table-Ordering System
**Base URL:** `http://localhost:8080`
**Contract:** [`docs/openapi.yaml`](openapi.yaml) — this file is the *single source of truth*. Everything below was executed against the running application and the **verbatim** responses are pasted in.

## 1. Conventions

| Aspect | Rule |
| :--- | :--- |
| Transport | HTTP/1.1, JSON only (`Content-Type: application/json`) |
| Authentication | HTTP session. `POST /api/auth/login` sets a `JSESSIONID` cookie; the response `token` field is that session id. Send the cookie on every staff call. |
| Customer access | No login. The table QR token in the URL path is the credential and is validated by `TableTokenInterceptor`. |
| Money | Stored `DECIMAL(10,2)`, transported as a JSON number with 2 decimals, handled as `BigDecimal` in Java. |
| Timestamps | ISO-8601 UTC, seconds precision: `YYYY-MM-DDTHH:mm:ssZ` |
| Prices from client | **Never accepted.** `POST /api/orders` has no price field; the server reads `price` from `menu_item`. |
| Error body | `{ "error": <CODE>, "message": <text>, "statusCode": <int>, "timestamp": <ISO-8601 UTC> }` (+ `details[]` for validation, + `expectedStatus`/`actualStatus` for 409) |

### Status code map

| Code | Meaning | Raised by |
| :--- | :--- | :--- |
| 200 | OK | reads, updates, login/logout |
| 201 | Created | place order, admin create |
| 400 | Bad Request / validation | `BadRequestException`, `MethodArgumentNotValidException`, `InvalidOrderStateException`, `EmptyOrderException`, `ItemUnavailableException` |
| 401 | Not authenticated | `AuthenticationException` (no/invalid session) |
| 403 | Wrong role | `ForbiddenException` (interceptor) |
| 404 | Not found | `TableNotFoundException`, `OrderNotFoundException`, `NoResourceFoundException` |
| 409 | Optimistic-concurrency conflict | `StatusConflictException` |
| 500 | Unexpected | catch-all handler |

All of these are produced centrally by [`GlobalExceptionHandler`](../src/main/java/com/restaurant/config/GlobalExceptionHandler.java).

### Try it in a browser

* Swagger UI: <http://localhost:8080/swagger-ui.html> (redirects to `/swagger-ui/index.html`)
* Raw contract: <http://localhost:8080/api-docs>

`/api-docs` is generated by SpringDoc from the Java annotations **and** augmented by [`OpenApiConfig`](../src/main/java/com/restaurant/config/OpenApiConfig.java) so that its `info.title`, `info.version` (`1.0.0`), `info.contact` and `servers` match `docs/openapi.yaml` exactly. The hand-written YAML is the richer document (examples per field, security schemes); the annotation-generated document is the executable one. Both describe the same 25 operations.

## 6. Customer — Orders

### 6.1 `POST /api/orders` — place an order

Body contains **only** `tableToken`, `specialNotes` and `items[{itemId, quantity, itemNotes}]`. No price is sent; the server reads `menu_item.price`.

```bash
curl -i -X POST http://localhost:8080/api/orders \
  -H "Content-Type: application/json" \
  -d '{"tableToken":"tok_tbl_05_e5b4a32109876543",
       "specialNotes":"Less spicy",
       "items":[{"itemId":6,"quantity":1},{"itemId":9,"quantity":2}]}'
```

```
201 Created
{"orderId":16,"sessionId":5,"tableNumber":"T05","status":"PLACED","totalAmount":1240.00,
 "specialNotes":"Less spicy","createdAt":"2026-10-18T22:39:56Z","updatedAt":"2026-10-18T22:39:56Z",
 "items":[{"orderItemId":44,"itemId":6,"name":"Butter Chicken","itemType":"FOOD","spiceLevel":"MILD",
           "volumeMl":null,"quantity":1,"unitPrice":420.00,"subtotal":420.00,"itemNotes":null},
          {"orderItemId":45,"itemId":9,"name":"Kadai Chicken","itemType":"FOOD","spiceLevel":"MEDIUM",
           "volumeMl":null,"quantity":2,"unitPrice":410.00,"subtotal":820.00,"itemNotes":null}]}
```

`unitPrice` is the DB snapshot at the moment of ordering. The whole request runs in **one** transaction — if any line fails, nothing is written.

### 6.2 `POST /api/orders` — failure modes

```bash
# (a) empty cart
curl -i -X POST http://localhost:8080/api/orders -H "Content-Type: application/json" \
  -d '{"tableToken":"tok_tbl_05_e5b4a32109876543","items":[]}'
# 400 {"error":"VALIDATION_FAILED", ...}

# (b) quantity out of the 1..20 range
curl -i -X POST http://localhost:8080/api/orders -H "Content-Type: application/json" \
  -d '{"tableToken":"tok_tbl_05_e5b4a32109876543","items":[{"itemId":6,"quantity":21}]}'
# 400 (quantity must be between 1 and 20)

# (c) item does not exist
curl -i -X POST http://localhost:8080/api/orders -H "Content-Type: application/json" \
  -d '{"tableToken":"tok_tbl_05_e5b4a32109876543","items":[{"itemId":99999,"quantity":1}]}'
# 400 {"error":"BAD_REQUEST","message":"Menu item not found: 99999", ...}

# (d) item exists but is sold out
# 400 {"error":"BAD_REQUEST",
#      "message":"Menu item 'Alphonso Mango Lassi' (ID: 25) is currently unavailable or sold out.", ...}

# (e) unknown table token
curl -i -X POST http://localhost:8080/api/orders -H "Content-Type: application/json" \
  -d '{"tableToken":"tok_nope","items":[{"itemId":6,"quantity":1}]}'
# 404 / 400 table not found
```

### 7.3 Repeating the same transition → **409 (concurrent click detected)**

The update is `UPDATE orders SET status = ? WHERE order_id = ? AND status = ?`. Two chefs clicking at once means the second gets 0 rows updated, which is reported as a conflict.

```bash
curl -i -b cookies.txt -X PATCH http://localhost:8080/api/orders/16/status \
  -H "Content-Type: application/json" -d '{"from":"PLACED","to":"ACCEPTED"}'
```

```
409 Conflict
{"error":"CONFLICT",
 "message":"Status conflict: expected current status was 'PLACED', but order #16 is currently 'ACCEPTED'.",
 "statusCode":409,"timestamp":"2026-10-18T22:40:05Z",
 "expectedStatus":"PLACED","actualStatus":"ACCEPTED"}
```

### 7.4 Illegal transition → **400**

`OrderStatus.canTransitionTo()` rejects anything outside the state machine.

```bash
curl -i -b cookies.txt -X PATCH http://localhost:8080/api/orders/16/status \
  -H "Content-Type: application/json" -d '{"from":"ACCEPTED","to":"SERVED"}'
```

```
400 Bad Request
{"error":"BAD_REQUEST",
 "message":"Cannot transition order #16 from current status 'ACCEPTED' to 'SERVED'. Allowed transitions: [PREPARING, CANCELLED]",
 "statusCode":400,"timestamp":"2026-10-18T22:40:05Z"}
```

### 7.5 The full happy path

```bash
for pair in "ACCEPTED PREPARING" "PREPARING READY" "READY SERVED"; do
  set -- $pair
  curl -s -b cookies.txt -X PATCH http://localhost:8080/api/orders/16/status \
    -H "Content-Type: application/json" -d "{\"from\":\"$1\",\"to\":\"$2\"}" | head -c 80; echo
done
```

```
200 OK   ... "status":"PREPARING" ...
200 OK   ... "status":"READY" ...
200 OK   ... "status":"SERVED" ...
```
